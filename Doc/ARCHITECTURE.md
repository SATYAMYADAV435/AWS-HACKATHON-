# KisanMitra — ARCHITECTURE

> Defines HOW the system is built. Language: **Python 3.12** for all application code.
> Exception: `frontend/speech.js` is the only JavaScript file — the Web Speech API (default STT/TTS) exists only in browsers and has no Python equivalent. It is a thin wrapper; all logic stays in Python.

## 1. System overview

```
Browser (mic, speakers, icons)
   │  speech.js: STT in / TTS out (Web Speech API, swappable)
   │  text + farmer profile + language
   ▼
POST /chat  ── Lambda Function URL (prod) or local_server.py (dev/backup)
   │
   ├─ router.py          1 Bedrock call → {intent, crop, language}
   ├─ agents/ (parallel per intent)
   │    weather.py   → tools/weather_tool.py  (Open-Meteo, cached fallback)
   │    land.py      → tools/regions.py       (regions.json lookup)
   │    market.py    → tools/mandi.py         (mandi_prices.csv, live API optional)
   │    crop_guide.py→ tools/kb.py            (Bedrock KB, S3/prompt fallback)
   ├─ recommender.py     plain Python: filter + rank + income math (NO LLM)
   └─ supervisor.py      1 Bedrock call → short card in user's language
   ▼
Answer card JSON → shown + read aloud in the same language
```

## 2. Components

| Component | Type | Input | Output |
|---|---|---|---|
| Supervisor | LLM (Bedrock) | Router result, farmer profile, language, agent findings | Final short card in the chosen language |
| Router | LLM (Bedrock) | Raw question text | `{intent, crop, language}` JSON |
| Weather agent | LLM + tool | 7-day forecast from Open-Meteo (free, no key) | Sow / irrigate / spray windows, green-amber-red |
| Land & Region agent | LLM + lookup | District → climate zone, typical soil, rainfall | Soil and region notes (typical, NOT a soil test) |
| Market agent | LLM + data | `mandi_prices.csv` (live API as bonus) | Current price and 30-day trend |
| Crop Guide agent | LLM + retrieval | Bedrock Knowledge Base (or S3 guide files in prompt) | How to grow, inputs, schedule, with sources |
| Recommender | **Plain Python code** | Season, soil, water filter; ranks by price trend; income = typical yield × price | Ranked crops with indicative income per acre |

## 3. Contracts (validate everything with `schemas.py`)

### Farmer profile
```json
{"district": "nashik", "acres": 3, "water_source": "well", "language": "mr"}
```

### Router output
```json
{"intent": "what_to_grow | weather_today | prices | how_to_grow | unknown",
 "crop": "onion | null",
 "language": "en | hi | mr"}
```

### Shared agent result (EVERY agent returns exactly this shape)
```json
{"agent": "weather",
 "finding": "max 2 sentences",
 "risk": "low | medium | high",
 "evidence": ["..."],
 "data_source": "open-meteo | cache | csv | kb | s3 | regions.json",
 "next_check": "string or null"}
```

### Answer card (what the frontend renders and speaks)
```json
{"title": "string",
 "summary_lines": ["max 3 short lines"],
 "steps": ["max 3 short lines, optional"],
 "labels": ["indicative", "before costs"],
 "sources": ["named source per how-to claim"],
 "speak_text": "plain text, read aloud verbatim",
 "language": "mr"}
```

Rules: schema validation failure → safe fallback response, never a crash. Numbers in cards come only from tools/data files, never generated by the LLM.

## 4. Request flow
1. Farmer taps mic and speaks (or taps an icon, or types). — Browser
2. Speech → text; text + profile + language → `POST /chat`. — Browser → backend
3. Router returns intent, crop, language. — Bedrock
4. Needed agents run in parallel (e.g., Weather + Land + Market for "what to grow"). — Backend
5. Recommender ranks crops; Crop Guide fetches the grow plan. — Backend
6. Supervisor writes the short card in the user's language. — Bedrock
7. Card shown and read aloud, with sources and an "indicative" label. — Browser

**Timeout:** Lambda Function URL (no API Gateway), Lambda timeout ~60 s. If responses exceed 20 s in testing, switch to job-ID + polling.

## 6. AWS services

| Service | Role | If cut |
|---|---|---|
| Amazon Bedrock | Router, agents, final card, hi/mr writing | Not cuttable — the core |
| AWS Lambda | Whole backend; Function URL = HTTPS endpoint | Not cuttable — local_server.py is the emergency backup |
| Amazon S3 | Crop guide documents and data files | Keep files in repo for demo |
| Bedrock Knowledge Bases | Cited retrieval over ICAR/agri-university guides (anti-hallucination) | Fallback: guide text into prompt with source names |
| Amazon Polly (optional) | Hindi read-aloud (Aditi, Kajal) | Browser voice |
| Amazon Translate (optional) | en → hi/mr with custom crop terminology, if LLM language quality fails the test gate | LLM-direct writing |
| Amazon Transcribe (optional) | AWS-native STT for Hindi | Browser or Sarvam |

Deliberately NOT used: SageMaker, AgentCore, Cognito, DynamoDB, CloudFront, API Gateway — setup cost without demo value.

## 7. Mode switches (.env — every dependency must have one)
```
USE_CACHE=true|false          # serve cached responses, no AWS calls
MANDI_MODE=csv|live           # default csv
KB_MODE=kb|s3                 # default s3 until KB is verified
LANG_MODE=llm|translate       # default llm
STT_PROVIDER=browser|sarvam   # default browser
TTS_PROVIDER=browser|polly|sarvam   # default browser
BEDROCK_MODEL_ID=...
BEDROCK_MODEL_ID_FALLBACK=...
```
Switches are read at startup, never hard-coded. Each provider/module implements the same interface so a switch is a config change, not a code change.

## 8. Fallback map (build these, don't just plan them)

| Failure | Fallback | Prepared artifact |
|---|---|---|
| Mic blocked / no speech recognition | Icon buttons + text box | Test on demo device, first 20 min |
| STT mishears Marathi | Show recognised text for correction; `STT_PROVIDER=sarvam` | voice_test_set.json, Sarvam key |
| No hi/mr voice on device | Polly (Hindi) / Sarvam (Marathi) / text + saved audio | Pre-generated audio |
| Marathi writing unnatural | `LANG_MODE=translate` for that language | Translate + custom terminology |
| Bedrock throttling/slow | Fallback model ID, else `USE_CACHE=true` | 2 models tested |
| Weather API down | Saved forecast | weather_cache/ |
| Mandi API down | CSV (the default) | mandi_prices.csv |
| KB slow/broken | `KB_MODE=s3`, guides into prompt | data/guides/ |
| Lambda timeout / CORS | Run local_server.py | Same code tested locally |
| Wi-Fi dies | Hotspot → cached responses | Demo build running from cache |

If a fallback is used live, say so — a labelled fallback is fine, a hidden one is not.

## 9. External data sources
- **Weather:** Open-Meteo API (free, no key). Cache per district the day before.
- **Mandi prices:** `mandi_prices.csv` snapshot is the default. Live API (data.gov.in or CEDA) is a bonus behind `MANDI_MODE=live`; needs a free key registered in advance.
- **Crop guides:** 8 text guides from ICAR / agri-university sources, each carrying source name, link, and date.
- Crop list (Maharashtra rabi, 6): wheat, gram, rabi jowar, onion, tomato, safflower — confirm against local sources when preparing data.
